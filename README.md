# Citeweb97

**CITEWEB, as it was in 1997.** CITEWEB was a French free web host (1996-1999, sold in 1999): free sites of up to 20 MB, e-mail, forums and a members' newspaper. This archive keeps the 1997 site: presentation and rules, CITENEWS, the forums page, the members' directory (logins and names, no passwords), the WebTrends statistics, and the sites it hosted at their original paths: DefCoN (`/defcon/`), .rIBBON! (`/ribbon/`), Citemag (`/citemag/`), AUTOMAG (dossier and classified ads, linked from `/automag/`). Orange Juice 1997 has its own archive: https://orangejuice97.sauthier.family

Archive of an old static website, served from bunny.net at the hostname
of [`site.json`](site.json). Kept online for history, no longer developed.

Full list of the sites: https://chanoj.github.io/

## How `site/` is made

`site/` is generated from the raw store (a Teleport Pro capture of the 1997 site, kept outside git) and committed:

```bash
./publish.sh
```

It runs `scripts/build.py` (lowercase names, `.htm` -> `.html`, `tppabs` attributes removed, links rewritten, dead internal links turned into plain text, external links kept as in the original except counters, search engines and server scripts, forms frozen, e-mail addresses of family names masked as `local＠????` while nicks and role addresses stay in clear, ages, postcodes, phone numbers and visitor host names removed, member lists by département left out; DefCoN, Citemag and AUTOMAG pages in a centred 800 px column; orphan pages linked from their section index), `scripts/seo.py` (`robots.txt`, `sitemap.xml`, 124 URLs, every published page), `scripts/verify_build.py` and `scripts/check_excludes.py`. It never deploys: merging to `main` does, through GitHub Actions.

Never published: engine code (`.asp`, `.inc`, `.dll`, `.exe`), counters, the 1998 redesign (its own archive), anything not in the 1997 capture.

Pages that show a family name, a full postal address or an e-mail whose local part is a family name end with "To be removed from this page, contact me."

## Layout

| Path | Content |
| --- | --- |
| `site/` | The website files, generated by `publish.sh`, exactly as served |
| `site.json` | The only site-specific settings: repository, storage zone, pull zone, hostname (plus zone ids, only until the first apply adopts them) |
| `infra/` | OpenTofu: storage zone, pull zone, hostname (state encrypted, committed) |
| `infra/secrets.env` | Proton Pass **references** to the secrets (vault `OldSites`), no secret values |
| `scripts/deploy.py` | Sync `site/` to the storage zone, purge the CDN |
| `scripts/smoke_test.py` | Check that the public site serves the files of `site/` |
| `publish.sh`, `scripts/build.py` | Build and check `site/` from the raw store |

DNS is not managed here: the hostname is a CNAME to `<pull zone>.b-cdn.net`
at Infomaniak.

## Deploying

- **Website**: push a change under `site/` to `main` → workflow *Website: deploy*
  uploads the changed files, deletes the removed ones, purges the CDN and runs
  the smoke test. A manual run allows a dry run. While the storage zone does not exist (before
  the first infra apply), it deploys nothing and only reports a notice.
- **Infra**: pull requests touching `infra/` show the plan; apply is a manual
  run of *Infra: bunny.net* (action `apply`, from `main`), which commits the
  encrypted state.

GitHub secrets: `BUNNY_API_KEY` (bunny.net account API key) and
`TF_VAR_STATE_PASSPHRASE` (state encryption), both from Proton Pass vault
`OldSites`. The storage zone password and pull zone id are looked up from the
API key, never stored.

Locally (Proton Pass CLI logged in):

```bash
pass-cli run --env-file infra/secrets.env -- python3 scripts/deploy.py --dry-run
```

```bash
cd infra && pass-cli run --env-file secrets.env -- tofu plan
```
