        1 -  What is da principe ?

        Si vous avez quelques difficultés avec l'organisation mémoire du PC je vais vous éclaircir une ch'touille. Le mode natif dont dispose tout processeur 80x86 (celui dans lequel il se trouve au
        démarrage) est le mode Réel : Votre machine est ici dans un adressage (mémoire) segmenté. Une adresse est composé d'un segment et d'un offset :

        ex: DS:SI

        Les registres de segments (ES, DS, SS, CS, FS, GS) et d'offset (SI, DI, IP, SP, BP) sont tout des registres 16 bits mais avec une particularité :

        Une adresse en mémoire se code sur 20 bits :

                  +----------------+   +---------------+
                  ¦Registre Segment¦ : ¦Registre Offset¦
                  +----------------+   +---------------+
          bits    19               3   15              0

        C'est donc bien mais pas top : on peut acceder jusqu'a 1 Mo de mémoire et y'a plein d'autres problèmes tous plus chiant les un que les autres...
         
        A partir du 80286 un type d'Intel qui gueulait plus fort que les autres (Et qui avait aussi plus de pouvoir que les autres :) ) à décidé de dévelloper le processeur x86 en le dotant d'un nouveau
        systeme de gestion de mémoire. Lorsque le 286 est sortie cela n'était pas encore au point mais le principe était lancé : Plus de mémoire et pis machin 'titache (M'titache ..... y'a des cons
        j'vous jure).         3 - DA Modez Protegez

        Trés sommairement voila de quoi il en retourne :

        Il existe 2 types de modèle mémoire :

           - Le modèle FLAT où vous avez un espace adressable unique de 4 Go (utilisé pour le flat realmode)

           - Le modèle "segmenté"

        Le modèle segmenté est dérivé du modèle FLAT voici comment cela fonctionne :
         
        Lorsque vous adressez la mémoire vous n'avez plus 1 Mo de limite mais 4 Go (Wahouuuuuuu) - adresse 32 bits. Mais cela d'une facon un peu spéciale. Voila un pointeur en mémoire :

             DS:ESI

        DS contient un nombre zoli et rigolo tandis que ESI contient un nombre codé sur 32 bits

        Bon sang mais pourquoi ???????????????????!!!!!!!!!!!!

        Le nombre contenu dans le registre de segment bah en fait il va référencer un sélécteur. Un sélécteur est un nombre qui pointe sur un descripteur de segment.

        Un descripteur de segment kézako ? (Désolé mais je fait ca de tête  alors si j'oublie des trucs c normal)

        C'est une structure qui définit dans un espace mémoire virtuel de  46 TeraOctet (32 bits d'adressage + 16384 selecteurs possibles):

            1 - Une adresse de base (dans la mémoire physique 4Go)
            2 - Une limite
            3 - Des droits d'acces
         
        ¦ L'adresse de base donne l'adresse Physique à laquelle commence le segment.
        ¦ La limite est la taille du segment.
        ¦ Les droits d'accés fixe les autorisations de Lecture/Ecriture sur le segment suivant votre nivo de privilège. (On verra plus tard comment modifier ses valeurs)

        Si vous ne pigez pas un traitre mot de tout cela, voici un petit exemple:

            DS = 240h
            ESI = 00000000

        DS référence le descripteur 240h or si on se reporte à notre table de descripteurs on peut s'apercevoir que le descripteur 240h possède les attributs suivant:
         
            Base adress : 000A0000h
            Limit       : 64 Ko
            Droits      : Lecture / écriture

        Cela veut dire que l'adresse pointée par DS:ESI (240:00000000) est  physiquement en 000A0000h !

         
         Adresse physique                   Adresse segmenté
                         |               |
            000AFFFFh    ¦_fin_de_segm___¦ 240 : 0000FFFFh
                         ¦               ¦
            000A0000h    ¦______base_____¦ 240 : 00000000
                         ¦               ¦
                         ¦    Mémoire    ¦
                         ¦               ¦
                         ¦               ¦
                         ¦               ¦
                         ¦               ¦
            00000000h    +---------------+
         

        Le segment 240h me permet donc d'adresser la zone mémoire de 000A0000h à 000AFFFFh (64 ko de limit).
         
        (Il faut noter que tout les descripteurs sont rangés dans 2 tables la GDT et la LDT. Il est possible de gérer jusqu'a 16384 sélecteurs. Dans la mesure où je ne tiens pas a faire du flat
        Realmode, n'en déplaise à certains, je n'expliquerais pas la structure de ces tables (En plus c long j'ai pas que ca à foutre))

        Les droits peuvent vous paraître idiot mais ils sont là dans un but précis : Souvenez vous le gars de chez intel qui voulait faire du multitache, et ben la paf bingo.
        Imaginez que vous vouliez faire tourner plusieurs programmes en  mémoire et bien un systeme Multi "Grosses" tâches va allouez a chaque programme des descripteurs pour son code et ses donnés. Mais chaque programme n'a pas le droits aux mêmes choses qu'un autre. C'est là que le fameux nivo de privilège entre en jeux :

        On distingue 4 types de codes et données executés par le système:

           - Le Noyau (Kernel)
           - Routines et données systèmes
           - Services système (une routine d'interruption par ex)
           - Applications

        Et bien chacun de ses élément à un niveau de privilège différent:
         
        Ex: - Seul le noyau peut modifier la table des decripteurs
            - Une application ne peut ecrire dans le segment de données
            systemes
            - etc...

        Bien entendu des mecs se cassent les couilles pour faire un truc à peu près potable ki marche, et voila que des gros bourrins cassent tout (cf Windaube 95)
         
         

        4 - Compatibilité 16/32 bits

        Le mode protégé semble bien jolie mais y'a tout de même comme un leger probleme. Le système d'exploitation DOS à été écrit pour le mode réel, y'a donc pas moyen d'avoir accés aux fonctions systèmes (essayez d'appeler l'int 21h en mode protégé vous verrez c rigolo)

        C'est alors que débarquèrent les DOS - EXTENDERS (non de zeus mais qu'est-ce ????)

        Un Dos extender permet de faire tourner un programme 32 bits sous DOS en évitant les inconvénients du modep. On peut prendre le cas, un peu spécial, de DOS4GW (voir aussi PMODEW ou DOS32)
         
        Ce dernier se trouve en mémoire lorsque un programme DOS 32 bits est lancé. Il va alors permettre un support quasi complet d'un système d'exploitation. Par exemple si votre prog fait appel à l'int 21h Dos4g executera sa propre int 21h ecrite pour le mode protégé. Cependant certaines int ne peuvent être éxecuter en Modep (Ex: Les fonctions BIOS pout des raisons évidentes) dans ce cas la dos4g va refaire passer le processeur en mode réel, éxecuter l'int
        et revenir en mode protégé (C un peu lourd mais bien utile)
         

        5 - Le DPMI

        Au lancement d'un programme, DOS4GW (ou PMODEW) initialise les segments de la facon suivante:

           ES = DS = SS (?) = CS (?) = segment de code + données
         
        Ce qu'a fait le dos extender, c'est qu'il a crée un selecteur pour  le code et les données et il lui file les attributs suivant :

           Base address : 0
           Limit        : Dépend de la taille de votre programme
           Droits       : Tous (Lecture / Ecriture)

        Ce qui est bien joli mais un petit peu dangereux quand on fait pas gaffe : Toute la zone de mémoire contenant le noyau est totalement déprotégé, il vous est donc possible d'écraser ce que bon vous semble (huh huh c rigolo ca fait tout casser .....)
         
        Cependant c bien joli mais comment fait on pour modifier la taille de ces segments, ou comment allouez de nouveaux selecteurs ???

        Vous pouvez le faire en bidouillant la table des descripteurs (Franchement faut vraiment se faire chier à ce niveau) ou alors passer par l'interface DPMI (Dos Protected Mode Interface) qui est
        à votre disposition. Cette dernière est appelée par l'int 31h et met en oeuvre toute les fonctions nécessaire à la manipulation de segments et autres choses en modep (voir n'importe quel programme genre DOSINT pour les references de l'int 31h)

        6 - Interruptions

        Il existe 2 types d'interruptions avec un Dos extender :

           - L'interruption en Mode réel
           - L'interruption en Mode protégé
         
        Comment est fait la distinction :

        En mode réel chaque int possède une adresse, toutes répertoriés dans la table des vecteurs d'interruptions.

        En mode protégé cette table est remplacé par l'IDT (Interrupt Descriptor Table) qui va contenir des descripteurs pour chaque routine.
         
        L'interruption en mode réel ne peut être appelé qu'explicitement. Pour cela il faut passer par un service de l'int 31h servant à  simuler un appel d'interruption en mode réel.(Ex: les services
        VESA doivent être appelé en mode réel)
         
        L'interruption en mode protégé est appelé comme en mode réel Ainsi, par exemple, tout service materiel IRQ GUS/SB peut être  déclenché en modep.

        Ex :

           NewIRQSB:
               pushad
               push ds

               mov ax,DGROUP        ; Si vous utilisé des données
               mov ds,ax            ; Pensez à recharger le descripteur
                                    ; dans DS
               ...
               ...

               mov al,20h           ; Acquitte le 8259
               out 20h,al

               pop ds
               popad

               iretd                ; iretd dépile les flags et l'adresse
                                    ; de retour far CS:EIP
         

        Ces handlers doivent être installé par l'int 21h. Le dos extender utilisera ses propres routines pour remplir l'IDT. Les fonctions 35h et 25h fonctionnent de manière transparente comme sous DOS.

         
             mov ah,35h
             mov al,[Intnum]
             int 21h
         
             mov [AncIntSel],es      ; Sauvegarde le selecteur et
             mov [AncIntOff],ebx     ; L'offset de l'ancienne routine
         
             mov ah,25h              ; Installe la nouvelle
             mov al,[Intnum]
             push cs                 ; DS contient le selecteur
             pop ds                  ; pour le code DS = CS
             mov edx,offset NewIRQSB ; EDX = offset de la routine dans le
                                     ; ségment
             int 21h

             ...
             ...

        Il est possible d'installer deux handlers pour la méme int : un en mode réel l'autre en modep (c ce k'on appel bimodal interrupt) J'en ai jamais vu l'intéret mais dans ce cas il faut modifier le fichier STUB.C qui sera éxecuter avant le chargement de DOS4G (en mode réel) Pour plus d'info la dessus voir les FAQS du watcom.

        7 - Les erreurs

        AHHHHHHHHH le domaine de prédilection de Micro..ft (Pas de pub :))
         
        A partir du 80386 le processeur est capable de générer des exceptions. Une exception intervient lorsque vous faite quelque chose que le processeur ne peut ou ne veut pas faire.
         
        Ex : Danser tous nu "oune doche treche, qui c'est qui va se taper Maria ?" ou encore faire croire que windaube marche bien et que tout va pour le mieux dans le meilleur des mondes (Vous pouvez pas savoir à quel point ca l'emmerde)
         
        C'est ce qu'il va se passer si vous tentez de lire un segment ou vous n'avez aucun droit en lecture, opcode inconnu, etc ......
